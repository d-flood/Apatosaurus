# Local SQLite Persistence Overhaul Plan

## Goal

Replace the app's `djazzkit`/Django-generated sync persistence layer with a local-only, database-first SQLite architecture that is simpler, faster, and easier to tune for browser usage.

The target design is raw SQL schema/migrations as the source of truth, generated TypeScript database types, Kysely-backed repositories, and a thin SQLite worker with coarse-grained domain operations.

## Assumptions

- No migration from existing browser `djazzkit` data is required.
- Existing browser `djazzkit` SQLite storage must be purged automatically before/while initializing the new local database.
- SQLite should remain off the main thread.
- The app, not Django, becomes the source of truth for local persistence.
- `djazzkit` should be removed from the repository entirely, including app imports, backend imports, root workspaces, package dependencies, generated artifacts, and the vendored `djazzkit/` directory.

## Target Architecture

- Raw SQL migrations live under `app/src/lib/client/db/migrations/`.
- A generation script applies migrations to a temporary SQLite database and emits `app/src/lib/client/db/types.generated.ts` using `kysely-codegen`.
- A dedicated local DB worker owns SQLite, Kysely, migrations, transactions, and repository execution.
- The main thread talks to the worker through a small typed RPC layer with domain-level methods, not one SQL call per row.
- App code imports domain storage functions such as `listTranscriptions`, `createProject`, `loadCollation`, `saveCollationProjection`, and `upsertCanvasAnnotation`.
- Domain DTOs use simple `id` fields rather than `_djazzkit_id`.
- Hard deletes replace `_djazzkit_deleted` soft deletes.
- Generic live query subscriptions are removed. Pages reload explicit lists after writes, with a tiny local invalidation event only where needed.
- A one-time legacy purge deletes old `djazzkit` IndexedDB and OPFS-managed SQLite files so users do not carry abandoned sync databases forward.

## Legacy Djazzkit Database Purge

Create `app/src/lib/client/db/legacy-djazzkit-purge.ts` and call it from `ensureLocalDbRuntime()` before opening the new database. This can run every startup because it is idempotent and targets only the old `djazzkit` storage namespace.

Implementation sketch:

```ts
const LEGACY_DJAZZKIT_IDB_DATABASES = ['djazzkit-idb'];
const LEGACY_DJAZZKIT_OPFS_PREFIX = 'djazzkit';

export async function purgeLegacyDjazzkitStorage(): Promise<void> {
	if (typeof indexedDB !== 'undefined') {
		const idbNames = await getLegacyIndexedDbNames();
		await Promise.allSettled(
			idbNames.map(name => deleteIndexedDb(name))
		);
	}

	if (typeof navigator !== 'undefined' && navigator.storage?.getDirectory) {
		await deleteOpfsEntriesWithPrefix(LEGACY_DJAZZKIT_OPFS_PREFIX);
	}
}

async function getLegacyIndexedDbNames(): Promise<string[]> {
	const names = new Set(LEGACY_DJAZZKIT_IDB_DATABASES);
	if ('databases' in indexedDB && typeof indexedDB.databases === 'function') {
		const databases = await indexedDB.databases().catch(() => []);
		for (const database of databases) {
			if (database.name?.startsWith('djazzkit')) names.add(database.name);
		}
	}
	return [...names];
}

function deleteIndexedDb(name: string): Promise<void> {
	return new Promise(resolve => {
		const request = indexedDB.deleteDatabase(name);
		request.onsuccess = () => resolve();
		request.onerror = () => resolve();
		request.onblocked = () => resolve();
	});
}

async function deleteOpfsEntriesWithPrefix(prefix: string): Promise<void> {
	const root = await navigator.storage.getDirectory();
	for await (const [name, handle] of root.entries()) {
		if (!name.startsWith(prefix)) continue;
		await root.removeEntry(name, { recursive: handle.kind === 'directory' }).catch(() => undefined);
	}
}
```

Notes:

- Keep this function independent from the new DB runtime so it still works if new DB initialization fails.
- Log purge failures at debug/warn level, but do not block app startup unless a failure clearly prevents opening the new database.
- If browser APIs lack `root.entries()` support in the target TypeScript lib, use the supported async iterator shape exposed by `FileSystemDirectoryHandle` with a narrow local type instead of weakening global types.
- Add a future cleanup note to remove this purge after enough greenfield builds have shipped.

- `_djazzkit_upload_queue`
- `_djazzkit_local_origin`

Schema conventions:

- Use `id TEXT PRIMARY KEY` for app-level IDs generated with `crypto.randomUUID()`.
- Remove integer Django `id` columns unless a table has a concrete need for row-local integer ordering.
- Remove `_djazzkit_rev`, `_djazzkit_deleted`, and `_djazzkit_updated_at` everywhere.
- Keep real app timestamps such as `created_at` and `updated_at` where the UI needs them.
- Store JSON payloads as `TEXT NOT NULL` containing serialized JSON.
- Enable `PRAGMA foreign_keys = ON`.
- Add `ON DELETE CASCADE` for derived child rows where deleting a parent should delete children.

Important constraints and indexes:

- `project_transcriptions`: unique `(project_id, transcription_id)` and indexes on both IDs.
- `transcription_verse_index`: unique `(transcription_id, verse_identifier)`, index `(verse_identifier, transcription_id)`.
- `collation_artifacts`: unique `(collation_id, artifact_type)`.
- `collation_witnesses`: unique `(collation_id, witness_id)`.
- `collation_tokens`: index `(collation_id, witness_id, token_index)`.
- `collation_variation_units`: index `(collation_id, start_index, end_index)`.
- `collation_readings`: unique `(variation_unit_id, reading_order)`.
- `collation_reading_witnesses`: unique `(reading_id, witness_id)`.
- `iiif_manifest_sources`: unique `(transcription_id, manifest_url)`.
- `transcription_page_canvas_links`: unique `(transcription_id, page_id, manifest_source_id, link_role)` and indexes on `canvas_id`, `manifest_source_id`.
- `iiif_canvas_annotations`: unique `(transcription_id, manifest_source_id, annotation_id)` and indexes on `canvas_id`, `page_id`.
- Add covering indexes for list pages: `transcriptions(updated_at DESC)`, `projects(updated_at DESC)`, `collations(updated_at DESC)`.

## Worker Runtime Plan

Build a thin local runtime in `app/src/lib/client/db/`.

`runtime.ts` responsibilities:

- Export `ensureLocalDbRuntime()`.
- Lazily create one worker instance.
- Serialize init so concurrent callers reuse the same promise.
- Call `purgeLegacyDjazzkitStorage()` before opening the new database.
- Expose `resetLocalDb()` and `checkpointLocalDb()`.
- Use a new DB/storage name such as `apatosaurus-local-v1`.
- Surface startup failures through the existing notification center with Reload and Reset local DB actions.

`db.worker.ts` responsibilities:

- Open the SQLite database.
- Run SQL migrations on init.
- Own the `Kysely<Database>` instance.
- Dispatch typed repository operations.
- Keep multi-row writes inside worker-side transactions.
- Emit simple domain invalidation events after successful writes.

`rpc.ts` responsibilities:

- Define a discriminated union of request/response types.
- Keep operation names domain-scoped, for example `transcriptions.list`, `transcriptions.createMany`, `collations.saveProjection`, `iiif.upsertAnnotation`.
- Avoid exposing a generic `query(sql, params)` API to app code except for internal maintenance/test utilities.

Performance constraints:

- Do not send hundreds of row-level messages between main thread and worker.
- Parse/serialize large JSON once per operation where feasible.
- Return list projections without large blobs, especially transcription `content_json`.
- Keep bulk import, verse indexing, collation projection replacement, and IIIF batch link saves as single worker calls.
