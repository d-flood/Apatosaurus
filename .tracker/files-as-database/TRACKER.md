# Tracker for files-as-database

## Purpose

This document tracks the status of all tickets in the files-as-database epic: invert the persistence hierarchy so that a project is a folder of versioned document files in OPFS and SQLite is a disposable, rebuildable index. Reference reading order: `architecture.md` (the target), `current-state.md` (the codebase as audited 2026-07-03, so you do not re-audit), `SPEC.md`, then the selected ticket.
