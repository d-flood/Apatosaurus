# 04 — Seed from a bundled reference edition

## What to build

The core of the epic: a scholar working in the transcription editor picks a passage from a bundled **reference edition** and **seeds** it into their document at the cursor. The inserted text arrives as unconfirmed text (ticket 02's mark).

This slice delivers the whole path — the reference edition source contract, off-main-thread parsing, Robinson-Pierpont bundled, a runtime catalog, a minimal picker, insertion, and the record of which editions a transcription was seeded from.

Demo: open a transcription, click Seed, choose Robinson-Pierpont, pick a verse, insert. The Greek appears at the cursor, highlighted as unconfirmed, carrying its book/chapter/verse milestones. The transcription now records that it was seeded from Robinson-Pierpont.

**This is the widest slice in the epic.** If it will not fit, split at the seam between the catalog-and-parse half and the insert-and-picker half rather than dropping contract items.

## Contract

**The source contract.** Packaging is outside the app's control — users will supply editions in shapes nobody chose. The only guarantees are:

```
listUnits(source)          -> ordered units, each with a milestone label and its content
extractRange(source, a, b) -> flat LineItem[] for units a..b inclusive (a may equal b)
```

Size, file count, and internal division are **unspecified**. Do not assume one book per file, a maximum size, or three levels of structure. How Robinson-Pierpont happens to be packaged is a convenience, not a contract.

**Addressing uses the existing three-level milestone structure**, whose level names are biblical but whose **values the app never interprets**. The parser already treats them as opaque strings; keep it that way.

- Ordering and contiguity come from **document order in the edition**, never from comparing or computing on label values.
- **Do not write a label parser.** No `parseVerseRef`, no chapter arithmetic, no "9 sorts before 10" logic. If you find yourself splitting a label to compare it, stop.
- Within one picker interaction the selection handle is **positional** in the unit list; the label is what is displayed and what rides into the inserted content. This makes an edition with repeated references usable rather than rejected, and guarantees the scholar gets the row they clicked.

**Flattening.** Page, column, and line breaks in a reference edition are dropped on extraction. Seeding **never changes the target's page, column, or line structure** — it changes only the items within one line. This is both mechanically necessary (`LineItem` has no break member; breaks are the edges between containers) and correct: a break in a source edition describes a *different* physical object.

**Insertion.** Content is spliced at the cursor inside the current line. Inserted text carries the `unconfirmed` mark from ticket 02, and its milestones, so the verse index and collation can find it.

**Parsing is off the main thread.** Both bundled and user-supplied editions go through the **same** `importTEIDocument` path. Do not add a build-time derived format — two parse paths would drift.

**The catalog is one runtime list from two sources:**

```ts
type ReferenceEditionSource = 'bundled' | 'user';
```

Both appear in one list to the scholar. Build the merged accessor now, implement the `bundled` branch, and have the `user` branch return `[]`. Ticket 06 fills it in. Do **not** build a second catalog, a second list UI, or a second import panel.

**Rejection and tolerance rules** (they belong to the source, so they land here even though user-supplied files arrive in 06):

- A source with **no milestones at all** is rejected. Its only possible action would be "insert the entire edition", which is the undifferentiated blob this feature exists to prevent.
- A source with **repeated milestone references** is accepted; positional selection makes it a non-event.
- A range whose start and end are the same unit is valid.

**Seeding writes no transcription record metadata** — not title, siglum, transcriber, repository, settlement, or language. This is the **opposite** of the existing TEI import path, which deliberately prefills those fields (see `TranscriptionForm.svelte`, the block that assigns from a metadata patch). Copying that block leaves a transcription of GA 1234 claiming to be Robinson-Pierpont. The only record field seeding touches is the editions-used set.

**Editions used** is a **set of edition identities, no ranges.** It never shrinks as text is edited. Range-level provenance is explicitly rejected: it goes stale the moment text is edited, split, or deleted.

**The minimal picker** for this slice is a flat, filterable list of unit labels with a start and end selection. Ticket 05 replaces its presentation.

**Attribution** is carried on each catalog entry as a string and displayed in the picker.

## Out of scope

- The hierarchical drill-down picker, range preview, and remembered position. Ticket 05.
- User-supplied editions, their registration UI, and their storage. Ticket 06.
- Rendering editions-used into the exported TEI header. Ticket 07.
- **Do not modify** `app/src/lib/client/transcription/igntp-import.ts`, `IgntpImportPanel.svelte`, or the IGNTP catalog. Reference editions superficially resemble that catalog and are a separate thing: the IGNTP catalog lists manuscript *witnesses*, and a printed edition is categorically not one.
- **Do not reuse** `buildTranscriptionDuplicateKey` (`app/src/lib/igntp/duplicate-key.ts`). It keys on siglum-or-title and is built for witnesses.
- **Do not** normalize orthography on seeding — no stripping diacritics, no case changes, no removing punctuation. Editions are seeded verbatim; curation happens in the source files.
- **Do not** strip edition-private word attributes such as `lemma` and `n`. Verbatim means verbatim; structural flattening is the single carve-out.
- **Do not** touch the collation `isBaseText` flag or the collation document format.
- **Do not** add offline pre-caching for editions. Existing asset caching already caches on first use.
- Multi-range selection in one insertion.

## Acceptance criteria

- [ ] Node spec: `listUnits` over a fixture edition returns units in document order with their milestone labels.
- [ ] Node spec: `extractRange` with equal start and end returns exactly one unit's content.
- [ ] Node spec: `extractRange` over a fixture containing `pb`/`cb`/`lb` returns flat content with no break items.
- [ ] Node spec: a fixture with no milestones is rejected; a fixture with a repeated reference is accepted and its two occurrences are separately selectable.
- [ ] Browser spec, via a harness: seeding a range inserts its text at the cursor, wrapped in `<seg type="unconfirmed">` on export, with verse milestones present.
- [ ] Browser spec: seeding does not change the number of pages, columns, or lines in the document.
- [ ] Browser spec: seeding leaves the transcription's title, siglum, transcriber, repository, settlement, and language unchanged.
- [ ] The transcription records Robinson-Pierpont in its editions-used set after seeding, and still records it after the seeded text is fully edited.
- [ ] Robinson-Pierpont is present under `app/static/` and appears in the catalog.
- [ ] Any new phosphor icon is added to `optimizeDeps.include` in `app/vite.config.ts`.
